# Topten Simple Theme Options

Theme options panel (STO) with autoload and singleton architecture. **Folder / text domain slug:** `battery-simple-theme-options`.

## WordPress.org slug collision — use a custom folder name

The WordPress.org plugin whose slug is **`simple-theme-options`** is **CHRS “Simple Tracking”** (analytics / social shortcodes), **not** this codebase. If you deploy this fork as **`wp-content/plugins/simple-theme-options/`**, **Dashboard → Updates** can overwrite it with Simple Tracking.

**Recommended:** clone into **`wp-content/plugins/battery-simple-theme-options/`** (or any name **other than** `simple-theme-options`). The bootstrap file sets **`Update URI: false`** so WordPress must not substitute the dot-org ZIP for this fork.

**PHP (new / changed code):** use descriptive variables — avoid opaque **`$v`**, **`$x`**, **`$c`** for real values; name by role (e.g. **`$option_value`**, **`$contact_url`**). Full-site Cursor guidance may live in the WordPress workspace **`.cursor/rules/php-descriptive-variables.mdc`**.

**Packaged demo:** Leaf section **Groups & panels** (`?section=groups-panels`) — **Group**, **Advanced repeater**, and **Accordion** samples in `includes/Admin/Sample/Fields/GroupsPanels/GroupsPanels.php`. Leaf section **Responsive** (`?section=responsive`) collects every sample field registered with `'responsive' => true` (device toolbar on titles). See `includes/Admin/Sample/Fields/Responsive/Responsive.php`.

**Premium (Freemius):** Pro field types — **Group**, **Tabs**, **Accordion**, **CodeEditor**, **RichModernEditor**, **DynamicObject**, **AdvancedRepeater**, **GoogleMap** — require **`topten_sto()->can_use_premium_code__premium_only()`** (helper **`sto_can_use_premium_fields()`**). When Pro is inactive, a full-width **Purchase Premium** banner appears above the Theme Settings panel title row (**`PremiumFieldGate::render_panel_banner()`**, **`sto-premium-locked.css`**); hide via filter **`sto_show_premium_panel_banner`**. The Freemius **Upgrade** WP submenu row and a matching **Upgrade to Pro** row at the bottom of the in-page Theme Settings sidebar use a shared purple→orange gradient (**`sto-freemius-upgrade.css`**, **`PremiumFieldGate::render_sidebar_upgrade_cta()`**). SDK loads via Composer **`vendor/autoload.php`** *before* **`includes/FreemiusBootstrap.php`**; init runs on **`plugins_loaded`** (priority 5) so themes can filter **`sto_freemius_menu_slug`** before connect. Default menu slug **`theme-settings`** (packaged demo); **Battery BD** sets **`uaebattery-settings`** so Account / Pricing nest under **UAEBattery** and the demo root can stay hidden when **Demo mode** is off. **Code editor fields:** **`CodeEditor::register()`** accepts **`html_required`** (paired with **`required`** visibility maps). ## Cursor / agent conventions

When changing this plugin in Cursor (or any assistant), follow **`.cursor/rules/simple-theme-options.mdc`** — especially the **Mandatory agent checklist** (viewport tiers, responsive **`device`** merge with the default trio, **`required`** eval at **`xxl`**, legacy **`lg`/`phone`** reads, short responsive tab **`title`** tooltips, **`FieldTitle`** layout — **`?` immediately after the title**; **scalar** fields keep device tabs in **`trailing_html`** on the right when used — **`getOptionFieldValue`** contracts, **§9 — new field types must implement `responsive` / `device`** end-to-end unless an explicit documented carve-out exists, **human-readable variable/array-key naming**, and **WordPress Coding Standards / PHPCS** as in **## PHP naming, array keys & WordPress coding standards** in that file). Update that rules file, **this README**, and **`wp-content/plugins/instructions/`** together when those contracts or integrator-facing behaviour change.

### Rules file lives in **two** locations (sync contract)

The same Cursor rules file is checked in at two paths so the conventions travel with the plugin even when it is downloaded / extracted on its own:

- **Plugin-local mirror (this download):** **`.cursor/rules/simple-theme-options.mdc`** at the **plugin root** — Cursor picks this up when the plugin folder is opened as a workspace (e.g. someone downloaded only this plugin and wants to extend it). All paths inside are written **relative to the plugin root**.
- **Site-wide copy (full WordPress install):** **`wp-content/plugins/simple-theme-options/.cursor/rules/simple-theme-options.mdc`** (relative to the WordPress install root, i.e. one folder above `wp-content/`). Cursor picks this up when the whole WordPress install is the workspace. Paths inside are written with the full `wp-content/plugins/simple-theme-options/` prefix.

**Sync rule (binding):** the **body of both files is the same**. Only the YAML frontmatter (`globs`), the short preamble, and the path prefixes differ. Any change to the conventions — new field type, new contract, new sample, new gotcha — **must** update **both** copies (and **`README.md`**, **`docs/RULES.md`** when workflow/policy changes, + **`wp-content/plugins/instructions/`** when applicable) in the same change set, **no matter which Cursor tab or prompt** produced the edit (Chat, Agent, Composer, or anything else — never update only one rules file in a turn). When you commit / push the plugin, both `.mdc` files travel together with the rest of the plugin source so the next Cursor session — wherever it opens the folder — gets the up-to-date guidance.

## Viewport breakpoints (built-in)

- There is **no** Theme Settings UI to edit breakpoint widths. Tiers are **fixed** in `SimpleThemeOptions\ViewportOptions::built_in_minimum_widths()` (Elementor-style min-width cascade: **mobile** from **320**, **sm** **576**, **md** **768**, **lg** **1024**, **xl** **1200**, **xxl** **1440**; **xs** min **0** = off). `get_minimums()` always returns this map (the `$sto_options` argument is ignored for thresholds).
- **Responsive fields:** With `'responsive' => true` and no **`device`** list, the admin shows the **default trio** tabs — **desktop (PC)** `xxl`, **tablet** `md`, **mobile** — in that order. With a non-empty **`device`** list, tabs are the **union** of that list and the default trio (de-duplicated, canonical **xxl → mobile** order), e.g. `array( 'lg', 'md', 'mobile' )` → **`xxl`**, **`lg`**, **`md`**, **`mobile`**. Storage keys match the shown tabs; `ResponsiveConfig::DEFAULT_RESPONSIVE_TABS` defines the default-only set. **Legacy:** maps saved with desktop under **`lg`** (old default trio) still load into the **`xxl`** tab on read via `ResponsiveConfig::raw_value_at_breakpoint()` until the user saves again.
- **PHP:** **`sto_get_option( $field_id, $default = null )`** — read one saved field by its registered **`id`** (same role as Redux `get_option( 'opt_name', 'field_key' )` except STO uses one global **`sto_options`** map, so you only pass the field key). **`sto_option_is_on( $field_id, $default = false )`** treats **`1` / `true` / `on` / `yes`** as enabled (switcher-like fields). **`sto_color_field_background_css( $field_id, $fallback_hex )`** and **`sto_color_string_to_background_css( $stored, $fallback_hex )`** format Color values for inline **`background-color`** (comma **`rgb()`/`rgba()`**). Also: `sto_get_options()`, `sto_get_responsive_option( $id, $viewport_width = null, $default = null )` (when `$viewport_width` is null, breakpoint maps use the **PC** eval slice `xxl`, same as `ResponsiveConfig::REQUIRED_EVAL_BREAKPOINT`), **`sto_resolve_responsive_breakpoint_map( $field_id, $defaults_per_breakpoint, $breakpoint_order )`** (cascade explicit tab values largest → smallest for CSS/builders), `sto_get_viewport_breakpoint( $width_px )`. Core logic: `ViewportOptions`.
- **Save:** Legacy keys `sto_adv_vp_*` in the database are unused for resolution; you may strip them in a custom `sto_options_before_save` filter if desired.
- **Front JS:** `add_filter( 'sto_enqueue_viewport_script', '__return_true' );` loads handle `sto-viewport` with localized `stoViewport.config` (thresholds + `evalBp`). Use `window.STOViewport.getValueForWidth( yourStoOptionsMap, 'option_id', window.innerWidth )` — pass the same shape as `sto_options` for that page (theme should localize or inline it).

## How main menu works

- Plugin boots on `plugins_loaded`.
- For **logged-in users with `manage_options`**, `SimpleThemeOptions\Plugin` loads **`Sample\Menu`** first (registers **`theme-settings`** via **`Options\Menu::register()`** — packaged demo is recognized by slug **`Menu::PACKAGED_DEMO_MENU_SLUG`**, not register args), then **`SampleFieldModules::boot()`**, **`ThemeSettingsImportExport`**, **`ThemeSettingsAdminBar`**.
- `Sample\Menu` attaches to `admin_menu`.
- **`Sample\Menu::init()`** only calls **`Options\Menu::register()`** to create the main admin menu (when the packaged demo is **on**):
  - Slug: `theme-settings`
  - Title: `Theme Settings`
  - Icon: `dashicons-admin-customizer`
- While the packaged demo is **off**, sample sections/fields are hidden but the **Theme Settings** menu stays (Freemius + license hub); use **Tools → Simple Settings → Demo mode** to show samples again. Themes that register their **own** menu slug (not **`theme-settings`**) get **Advance** (import/export) and client-only export keys.
- **Multiple top-level menus:** Call **`Options\Menu::register()`** again with a different slug (e.g. **UAEBattery** alongside **Theme Settings**). **`is_menu_root_packaged_demo( $slug )`** is true only for **`Menu::PACKAGED_DEMO_MENU_SLUG`** (filter **`sto_packaged_demo_menu_slugs`**). Sections remember **`sto_menu_page`**, or pass **`'sto_menu_page' => 'your-slug'`** in section args. **`get_parent_menu_slug()`** stays the **first** slug; use **`get_request_options_menu_slug()`** for the current screen.

## Select field usage

Sample option fields are split by **leaf `section_slug`** under **`includes/Admin/Sample/Fields/{Section}/{Section}.php`** (e.g. **`Fields/General/General.php`** registers **`layout-nav`**, **`layout-tabs-side`**, etc.; **`Fields/Appearance/Appearance.php`** for **`appearance-color`** and siblings). Parents such as **`field-samples`** are defined only in **`Sample\Sections.php`** (nested nav). Field **`register()`** calls may live directly in each class’s **`init()`** — they are applied when **`Options\Menu::register()`** runs **`include_fields()`** / `do_action( 'sto_include_option_fields' )` (internal flush at priority **`0`**). You can still attach your own callbacks on **`sto_include_option_fields`** if you need custom logic around registration. **`Sample\Menu`** boots **`Fields\General\General`**, **`Fields\Appearance\Appearance`**, etc., **before** `register_menu()` so **`init()`** runs before the menu builds.

You can also register select fields by config anywhere early in admin bootstrap:

```php
use SimpleThemeOptions\Admin\Options\Fields\Select\Select;

Select::register(
    array(
        'section_slug' => 'layout',
        'id' => 'layout_header',
        'title' => 'Header',
        'placeholder' => 'Select',
        'description' => 'Set your default header for all pages.',
        'default' => 'default_header_layout',
        'options' => array(
            'none' => 'None',
            'default_header_layout' => 'Default header layout',
        ),
    )
);
```

Supported keys:
- `section_slug` (required)
- `id` (required)
- `options` (required, value => label)
- `title`, `description`, `default`, `placeholder`, `class`, `wrapper_class`, `required`, optional `responsive` (see **Responsive breakpoints** below), optional `device` (extra slugs merged with the default trio — see **Viewport breakpoints**)
- `tooltip` / `tooltip_image` / `tooltip_preloader` (optional image help; see **Image tooltip** above)
- optional **`multiple`** (bool) — render as a Select2 multi-select. Selected values appear as **blue chips** with a "×" remove control before the label (`.select2-selection--multiple` + `.select2-selection__choice` styled in `sto-select2.css`). Stored as **`array<int, string>`** in `sto_options[id]` (or `array<bp, array<int, string>>` when `responsive`); cleared selections persist as `[]` via `Select::merge_missing_multiple_select_fields()`. `placeholder` becomes the empty-state hint (chip area shows it when no value is picked).
- optional **`max`** (int) — when `multiple` is true, max simultaneous selections (Select2 `maximumSelectionLength`). `0` = unlimited (default); capped at `100`.
- **`default`** for multi: `array` of option keys or comma list (`'a,b'`); unknown keys are dropped.
- **`required` matching against a multi-select:** `getOptionFieldValue()` and PHP `RequiredVisibility` both **join selected values with `,`** (alphabetical order **not** enforced — the order matches what the user picked). So `required: { my_select: 'shop_page' }` matches **only** when `shop_page` is the **only** selected value. Use a single-value select when you need a strict equality dependency.

### Required / conditional visibility rules (project convention)

Use `required` rules to show/hide a field dynamically based on other field values.  
This runs on each field change in admin UI.

- Direct format (single rule group):
```php
'required' => array(
    'layout_header' => 'none',
),
```
- Nested format (multiple OR groups):
```php
'required' => array(
    array( 'layout_header' => 'none' ),
    array( 'site_width' => 'boxed' ),
),
```

Rule behavior:
- Inside one group, conditions are `AND`.
- Across multiple groups, matching is `OR`.
- If no group matches, field is hidden and its inputs are disabled.
- After rules run, **group panels** with no visible inner content (all inner fields/subgroups hidden) get **`sto-field-group--empty-body`** so the empty box and heading are not shown (`main.js`: `markEmptyFieldGroups`).

**JS implementation note:** `main.js` **`getOptionFieldValue( fieldKey, contextBp )`** reads `sto_options[fieldKey]` from the DOM. For **conditional `required`**, **`applyRequiredVisibility`** always calls **`getOptionFieldValue( fieldKey, '' )`**: responsive dependencies use the **PC / eval** breakpoint only — **`data-sto-require-eval-bp`** on the **dependency** row (usually **`xxl`**, or the first tab when that breakpoint is not shown), not the dependent row’s active device tab. For non-responsive dependencies, use the single control value. Responsive fields use **`sto_options[fieldKey][breakpoint]`** (and **`[]`** for DynamicObject multiple). **Typography** / **Background control** / **Range** / **Gallery**: per-pane or single hidden JSON string. **Classic `wp_editor`**: **`readInputValue`** / TinyMCE **`getContent({ format: 'text' })`** when the visual editor is active.

### Responsive breakpoints (optional)

On **Switcher**, **CheckboxControl** (single and multi), **Select**, **Button group**, **Image select**, **Color**, **Input** (all input types **except** `editor`), **Typography**, **Background control**, **Range**, **Date field**, **Date + time field**, **Dimension**, **Gallery**, **Alignment**, and **Dynamic object**, add:

- `'responsive' => true` — or any non-empty array: opts into per-breakpoint storage. With no **`device`** list, the UI stores the **default trio**: **`xxl`** (PC), **`md`** (tablet), **`mobile`**. With a non-empty **`device`** list, tabs are the **union** of that list and the default trio (de-duplicated, canonical **xxl → mobile** order). (A non-empty `responsive` array only opts in; it does not list devices.)

- Optional **`'device' => array( 'lg', 'xl', … )`**: extra canonical slugs **merged** with **`xxl`**, **`md`**, **`mobile`**; invalid entries are ignored. Omit `device` or use an empty array for the default trio only.

**Saved option shape:** `sto_options['your_id']` is either a **scalar / single JSON string** (legacy / non-responsive) or an **associative array** with **one key per shown breakpoint** (e.g. **`xxl`**, **`md`**, **`mobile`** for the default trio). Legacy full maps may include every key; legacy maps may use **`phone`** instead of **`mobile`**; the plugin reads **`phone`** as **`mobile`**.

**Conditional `required` (admin JS):** Visibility always compares against the **eval / PC** slice for responsive dependencies (**`data-sto-require-eval-bp`**, default **`xxl`** — same as **`ResponsiveConfig::REQUIRED_EVAL_BREAKPOINT`**), not the tablet/phone tab the user has open on another row. **`data-sto-active-bp`** on a row only tracks which pane is visible for editing; it does not drive `required`. **Server-side** visibility uses **`RequiredVisibility`** + **`ResponsiveConfig::value_for_required_eval()`**. **Non-responsive** dependency rows expose a single input name.

**UI:** Breakpoint controls are **Font Awesome device icons** in the **title row** on the **right** (**.sto-field-title-row__trailing**). The image **`?`** help sits **directly after the field title** (leading cluster), not beside the device tabs. Hover a tab for a short native **`title`** hint (**XXL**, **Tablet**, **Mobile**, etc.); **`aria-label`** still carries a fuller name for assistive tech.

**New field types — required contract:** Any new option control must be **fully compatible with `required`**: correct **`data-sto-required`** on the wrapper, real **`:input`** values readable by **`getOptionFieldValue`**, inputs disabled when the row is hidden, **`change`** firing so dependents update, and **`refreshStoSelect2()`** / re-init where needed. Test the field both **as** a dependency and **with** dependencies before considering the feature complete. See **`.cursor/rules/simple-theme-options.mdc`** (Responsive breakpoints + Conditional visibility — mandatory checklist).

For other field types, follow the same convention by outputting `data-sto-required` on the field wrapper with the same JSON schema.

Inner field configs use the same keys as `Select::register()` (except `section_slug` is set by the group) **unless** the entry uses **`type` => `dynamic_object`**, **`type` => `image_select`**, **`type` => `button_group`**, **`typography`**, **`color`**, **`background_control`**, **`border`**, **`code_editor`** (aliases **`codeeditor`** / **`code`**), **`link_color`**, **`switcher`**, **`range`** (optional **`units`** array: any ordered non-empty subset of **`px`**, **`%`**, **`rem`**, **`em`**, **`custom`**; optional **`unit_label`**: UI-only text after the number; with **`units` => array( 'custom' )** only, hides the suffix input and CUSTOM badge), **`type` => `tabs`** (see **Tabs** below), **`type` => `accordion`** (see **Accordion** below), or a **plain input** type (**`text`**, **`number`**, **`textarea`**, **`editor`**, **`email`**, **`phone`**, **`search`**, **`password`**) / **`type` => `input`** with **`input_type`**. Any inner entry — including **nested subgroups** — may also set **`width`** as **`1-2`**, **`1/2`**, **`1-3`**, **`2-3`**, **`1-1`**, **`full`**, **`100%`**, or an integer **1–12** to lay out side-by-side on the group's built-in **12-column grid**. Default = **`12`** = full row (looks identical to the legacy stacked layout). Cells stack one-per-row at **`@media (max-width: 960px)`** so the width is never lost on narrow admin / mobile. Keep each visual row's spans summing to **≤ 12** or the grid wraps mid-row. Parser lives in **`Common\LayoutWidth::parse_span()`** and is shared with **Tabs** so the grammar is identical. **Nested groups:** any entry in `fields` that has a `fields` array (and no top-level `options`) is treated as a subgroup—same keys as the root config (`id`, `title`, `fields`, optional `description`, `required`, optional `width`, optional **`tooltip`** / **`tooltip_image`** for the subgroup `<h3>`). Nesting can repeat to any depth. Subgroup `required` rules apply to that panel only (see `Sample/Fields/General/General.php` sample `sidebar_layout_extras`). **Root `Group::register()`** may also set **`tooltip`** / **`tooltip_image`** / **`tooltip_preloader`** for the root panel heading (same floating image preview as inner fields).

```php
Group::register(
    array(
        'section_slug' => 'layout',
        'id'           => 'portfolio_url',
        'title'        => 'URL',
        'fields'       => array(
            array( 'type' => 'text', 'id' => 'portfolio_project_slug',  'title' => 'Portfolio project URL slug',  'placeholder' => 'portfolio',          'width' => '1-2' ),
            array( 'type' => 'text', 'id' => 'portfolio_category_slug', 'title' => 'Portfolio category URL slug', 'placeholder' => 'portfolio-category', 'width' => '1-2' ),
        ),
    )
);
```

**Tabs (`type` => `tabs` in a group, or `Tabs::register()` standalone):** horizontal tabs with a shared inner **`fields`** template repeated per tab. Keys: **`section_slug`** (standalone only), **`id`** (prefix for stored keys), **`title`**, **`tabs`** => **`array( array( 'id' => 'b1', 'label' => 'Button [1]' ), … )`**, **`fields`** => inner configs (same types as Group except no nested **`tabs`** / subgroup **`fields`**), optional **`responsive`**, **`device`**, **`description`**, **`required`**, **`tooltip`** / **`tooltip_image`**, **`wrapper_class`**. When **`responsive`** is set, the **Tabs** row shows **one** heading line via **`FieldTitle::render_heading( …, $trailing_html, $between_html )`**: **title + ?** (left), **horizontal tab strip** (visual center via **CSS grid** **`1fr` · `auto` · `1fr`** on **`.sto-field-title-row--tabs-master`**); **no tab-level device toolbar** — each **inner field** in the pane’s **`.sto-tabs__grid`** renders its own **`ResponsiveControl`** UI (**`data-sto-responsive="1"`** on that field’s **`.sto-field-row`**) so every column / control has **independent** desktop / tablet / mobile selection. **`Tabs`** does **not** set **`ResponsiveConfig::PARENT_RESPONSIVE_PANE_BP`** on inners ( **`render_tabs_stack`** passes **`null`** ), so each inner behaves like a normal responsive field. **`sto-tabs.js`** keeps the **master** Slot A/B strip in sync (**`data-sto-tabs-master="1"`**, **`data-sto-sync-tab`**) via **`$outer.children('.sto-tabs')`**. **Registration:** inner clones set **`group`** (the **`Tabs` `id`** when standalone, otherwise the parent group id) and **`ResponsiveConfig::TABS_INNER_FIELD`** so **`render_section_fields`** does **not** print duplicates. Each inner item may set **`width`** to **`1-2`**, **`1/2`**, **`1-3`**, **`2-3`**, **`1-1`**, **`full`**, or an integer **1–12** for a **12-column** grid inside the pane (**keep each row’s spans summing to ≤12** for a stable layout). **`sto-tabs.css`**: inner cells go **full width** at **max-width 960px**; responsive inner title rows inside cells **wrap** when narrow; the **responsive** master title row (title · tab strip only) stacks at **782px** (WordPress narrow admin). The **title row** uses no panel background or border; only the **tab content pane** is the light gray card (**`sto-tabs.css`**). **Non-responsive** tabs keep the previous pattern: title row with tab strip in **`$trailing_html`** (right). The tabs **heading** is **larger** than tab labels; **inactive** tab buttons stay **fully transparent** (no WP gray button fill); only the **active** tab gets the light gray chip + blue label. Stored keys: **`{tabs_id}_{tab_id}_{inner_field_id}`** (e.g. `layout_cust_btn_b1_btn_url`). Assets **`sto-tabs`**; **`main.js`** calls **`stoInitTabsControls`** with **`refreshStoSelect2()`** so Select2 / color init runs after switching tabs or changing any inner field’s device tab. Samples: **Layout** → **Standalone tabs (responsive demo)** and **Custom buttons (tabs demo)** in **`General.php`**.

**Accordion (`type` => `accordion` in a group, or `Accordion::register()` standalone):** vertical sections with the same shared **`fields`** template per **`panels`** entry. Keys mirror **Tabs** but use **`panels`** => **`array( array( 'id' => 'general', 'label' => 'General' ), … )`**. One section is expanded at a time (**`sto-accordion.js`**). With **`responsive`**, the title row gets a **master** strip (**`data-sto-accordion-master="1"`**, **`data-sto-sync-accordion-pane`**) like responsive **Tabs**; inner fields still each render **`ResponsiveControl`**. Inner clones use **`ResponsiveConfig::ACCORDION_INNER_FIELD`**; stored keys **`{accordion_id}_{panel_id}_{inner_id}`**. Assets **`sto-accordion`**; **`main.js`** calls **`stoInitAccordionControls`** from **`refreshStoSelect2()`** / **`initStoResponsiveTabs`**. Sample: **Groups & panels** (`groups-panels`) in **`GroupsPanels.php`**.

**Dynamic Object (`dynamic_object`):** add **`'type' => 'dynamic_object'`**, **`id`**, **`post_type`**, optional **`multiple`** (bool), **`max`** (max selections when multiple), **`limit`** (max posts **per AJAX page**, default **10** — not preloaded into HTML), **`search_min_length`** (default **3**; AJAX + Select2 **`minimumInputLength`**), **`post_status`**, **`placeholder`**, **`default`** (post ID string, or array / comma list when **`multiple`**), **`required`**, **`tooltip`**. Renders like **Select** but choices come only from **AJAX** **`sto_dynamic_object_search`** after typing enough characters. Standalone: **`DynamicObject::register( array( 'section_slug' => …, 'id' => …, 'post_type' => 'product', … ) )`** — boot **`DynamicObject::instance()`** before **`Group::register()`** when used inside groups.

**Image group select (`image_select`):** add **`'type' => 'image_select'`**, **`id`**, **`title`**, **`options`** where each **key** is the stored value. Each value is either a **label string** (preset guessed from key) or **`array( 'label' => '…', 'image' => 'https://…' )`** for a **custom thumbnail** (recommended). Omit **`image`** and set **`preset`** to **`full` \| `sidebar_left` \| `sidebar_right`** to use the built-in wireframe. You can register **any number** of options. Optional **`description`**, **`required`**, **`tooltip`**, **`columns`** (int **1–12** OR keyed map: **`xxl`** desktop, **`md`** ≤991px, **`mobile`** ≤600px — missing tiers cascade up; CSS Grid fills the panel **100%** of width), **`show_labels`** (bool, default **`true`** — set **`false`** to hide visible captions). Each thumbnail always shows the option **`label`** on hover / keyboard focus via the shared **`#sto-text-tooltip`**, so admins can identify tiles even when columns are narrow.

Section output order on `sto_render_section_content` is fixed by hook priority: **standalone ImageSelect** `17` → **standalone ButtonGroup** `17.5` → **standalone RadioListsControl** `17.55` → **standalone Select + DynamicObject + Switcher + CheckboxControl** `18` → **standalone Color** `19` → **standalone BackgroundControl** `19.25` → **standalone LinkColor** `19.3` → **standalone BorderControl** `19.30` → **standalone ShadowControl** `19.31` → **standalone GradientControl** `19.32` → **standalone Range** `19.35` → **standalone DateField** `19.38` → **standalone DateTimeField** `19.39` → **standalone Dimension** `19.42` → **standalone MultiTextControl** `19.435` → **standalone GalleryControl** `19.43` → **standalone AlignmentControl** `19.44` → **standalone GoogleMapControl** `19.441` → **standalone IconSelect** `19.442` → **standalone Tabs** `19.45` → **standalone Accordion** `19.46` → **standalone CodeEditor** `19.55` → **standalone Input** `19.5` → **standalone Typography** `20` → **Group** `21`. Select, DynamicObject, Switcher, and CheckboxControl share priority `18` (first registered renders first—boot **`Switcher::instance()`** before **`Select::instance()`** if switchers should appear above selects; boot **`CheckboxControl::instance()`** when you need custom checkbox rows in a stable position in that band; register **`DynamicObject`** after **`Select`** in the same callback if CPT rows should follow static selects). Boot **`ImageSelect::instance()`** before **`ButtonGroup::instance()`** before **`RadioListsControl::instance()`** before **`Select::instance()`** if standalone image rows should print first, then segmented button groups, then radio-list repeaters, then plain selects. Fields **inside** a group still follow the order of that group’s `fields` array. Quick search paths use `Group::get_group_breadcrumb_titles()` for nested titles.

### Image tooltip (all field types + group headings)

```php
	'image' => 'https://example.com/preview.png',
),

// Optional: replace the default spinner with your own image or short video while `image` loads.

```

### Image group select field

- Class: **`SimpleThemeOptions\Admin\Options\Fields\ImageSelect\ImageSelect`**. Boot **`ImageSelect::instance()`** before **`Group::register()`** when using it inside groups.
- **Standalone:** `ImageSelect::register( array( 'section_slug' => '…', 'id' => '…', 'title' => '…', 'options' => …, … ) );`
- **Inside a group:** `'type' => 'image_select'` plus `id`, `title`, `options`, optional `default`, `description`, `required`, `tooltip`, **`columns`**, **`show_labels`**.
- **`options`:** map **value** (stored string) → **`label` string** or **`array( 'label', 'image' => URL )`** for thumbnails; or **`preset`** only when you want the built-in wireframe instead of **`image`**.
- **`columns`** (optional): integer **1–12** for the same column count on every admin viewport, **or** a keyed map limited to **`xxl`** (default / desktop), **`md`** (≤991px), **`mobile`** (≤600px). Larger / smaller canonical slugs (**`xl`**, **`lg`**, **`sm`**, **`xs`**, legacy **`phone`**) collapse onto the nearest tier; missing tiers cascade up (mobile → md → xxl). PHP emits inline CSS custom properties (**`--sto-img-cols-xxl|md|mobile`**) on **`.sto-image-select`**; CSS Grid (`grid-template-columns: repeat(N, minmax(0, 1fr))`) makes tiles fill the panel **100%** of width. Built-in fallback when omitted: **3 / 2 / 1**.
- **Hover tooltip:** every option **`<label>`** carries **`data-sto-text-tip`** equal to the option **`label`**, so hovering or keyboard-focusing any thumbnail shows the label in the shared **`#sto-text-tooltip`** popover (positioned automatically by **`main.js`** `stoTextTooltips`). Visible captions under each thumb still print by default; **`show_labels` => false** hides them while the hover tooltip remains.

### Checkbox / multi-check field (`checkbox`)

- Class: **`SimpleThemeOptions\Admin\Options\Fields\CheckboxControl\CheckboxControl`**. Boot **`CheckboxControl::instance()`** before registering (same hook band as **Switcher** / **Select** — priority **`18`** on **`sto_render_section_content`**).
- **`CheckboxControl::register()`** / **`register_many()`**: **`section_slug`**, **`id`**, optional **`title`**, **`description`**, **`multiple`** (bool). **Single** (default): optional **`default`** `1`|`0`, optional **`labels`** (`on` / `off` strings for the tile caption). **Multi**: **`options`** required (value → label string or `array( 'label', optional 'tooltip' )`), optional **`default`** (array or comma list of keys), optional **`max`** (0 = unlimited), optional **`columns`** (1–6 fixed grid; 0 = auto-fill), optional **`responsive`**, **`device`**, **`required`**, **`tooltip`**, **`wrapper_class`**, **`group`**.
- **Inside a group / Tabs / Accordion:** **`'type' => 'checkbox'`** plus the same keys (omit **`section_slug`** in inner arrays).
- **Stored value:** single → **`1`** or **`0`** (scalar or per-breakpoint map). Multi → **`array<int, string>`** of option keys (or per-breakpoint map of arrays). Unchecked multi POST omits keys — **`CheckboxControl::merge_missing_multiple_checkbox_fields()`** (from **`Menu::maybe_handle_save_request()`** after **`Select::merge_missing_multiple_select_fields()`**) persists empty arrays. Save uses **`CheckboxControl::sanitize_posted_value()`**.
- **Assets:** **`sto-checkbox`** CSS (**`sto-checkbox.css`**, deps **`sto-style`**, **`sto-switcher`**, **`sto-responsive`**) and JS (**`sto-checkbox.js`**); **`display-section-on-menu`** depends on **`sto-checkbox`** so **`window.stoInitCheckboxControls`** exists before **`main.js`** runs. **`sto-select2`** CSS depends on **`sto-checkbox`** so Theme Settings always loads tile rules. **`main.js`** calls **`stoInitCheckboxControls`** from **`refreshStoSelect2()`** and the responsive tab handler; **`getOptionFieldValue`** reads responsive multi-check panes correctly (multiple **`type="checkbox"`** with the same **`name`**).
- **JS behaviour:** single mode toggles a hidden input via the tile button; multi mode keeps **screen-reader-only** native checkboxes in sync with tiles and enforces **`data-sto-checkbox-max`** per stack.

### Button group field (`button_group`)

- Class: **`SimpleThemeOptions\Admin\Options\Fields\ButtonGroup\ButtonGroup`**. Boot **`ButtonGroup::instance()`** before **`Group::register()`** when using it inside groups (after **`ImageSelect`** if both are used in standalone output order).
- **Standalone:** `ButtonGroup::register( array( 'section_slug' => '…', 'id' => '…', 'title' => '…', 'options' => …, … ) );`
- **Inside a group:** `'type' => 'button_group'` plus `id`, `title`, **`options`**, optional `default` (must match a value key), `description`, conditional visibility on **other** fields: **`'required' => array( 'this_field_id' => 'value_key' )`**, optional row **`tooltip`** / **`tooltip_image`**.
- **`options`:** map **value** → **label string** or **`array( 'label', optional 'tooltip', optional 'preview_image' )`**. Per-segment **`?`**: **`tooltip`** only → **`#sto-text-tooltip`** (**`data-sto-text-tip`**). **`preview_image`** → same **`#sto-field-help-popover`** as **`FieldTitle`** (**`data-sto-tooltip-image`** on hover / focus); **no** inline preview strip. If both keys are set, hover shows the **image**; plain text remains in **`aria-label`**. Up to **12** options.
- Save path: **`Menu`** calls **`ButtonGroup::sanitize_for_field()`** for registered ids. **`get_option_value()`** treats a stored empty string as missing and falls back to **`default`**. **`main.js`**: radios use **`getOptionFieldValue`** (`:checked`); **`initStoButtonGroups`** syncs **`.sto-button-group__segment--selected`** and re-runs **`applyRequiredVisibility`** on init and **`change`** so fields with **`required` => array( 'button_group_id' => 'value_key' )** show/hide when the segment changes. Image help listens on **`.sto-field-help-trigger`** and **`.sto-button-group__hint[data-sto-tooltip-image]`** (**`mouseenter` / `focusin`**).
- **Chrome:** **`sto-button-group.css`** — **`width: fit-content`** on the wrap + **`inline-flex`** on the bar (**`overflow-x: auto`** on the wrap when needed); each **`.sto-button-group__segment`** is **`flex: 0 0 auto`** with **`min-width: min-content`** so option width follows label + **`?`** (**`gap: 6px`**). **#e0e0e0** border, **5px** outer radius, **3px** inner padding and **2px** gutters; inactive **400** / **#3c434a**, active **700** / white; **16px** inline **`?`**. The **radio + caption** sit in **`<label class="sto-button-group__choice">`** with **`min-width: min-content`** so the label does not shrink under the text; the hint stays **`type="button"`** so it does not change the selection.

## Local dev troubleshooting

### "Error establishing a database connection" on Local (by Flywheel) — Windows

**Symptom:** Starting the site in Local shows the WordPress error "Error establishing a database connection" even though Local says the site is running.

**Root cause:** Each Local site runs its own MySQL on a unique port (e.g. `10175`). Local's PHP picks up that port from the per-site `php.ini` (`mysql.default_port`, `mysqli.default_port`, `pdo_mysql.default_port`). When MySQL gets reassigned to a new port (Local update, port conflict, manual stop/start) and `php.ini` is not regenerated, PHP keeps trying the **old** port. `wp-config.php` only has `DB_HOST = 'localhost'` (no port), so `mysqli` falls back to that stale port and the connection fails.

**How to confirm:**

1. Find the running MySQL port for the site (PowerShell):

   ```powershell
   Get-CimInstance Win32_Process -Filter "Name = 'mysqld.exe'" |
     Select-Object ProcessId, CommandLine | Format-List
   ```

   The `--defaults-file=...\run\<siteId>\conf\mysql\my.cnf` reveals the site id; open that `my.cnf` and read its `port = NNNNN`.

2. Compare against `port` values inside:
   `C:\Users\DELL\AppData\Roaming\Local\run\<siteId>\conf\php\php.ini` (`mysql.default_port`, `mysqli.default_port`, `pdo_mysql.default_port`). If they differ, this is the bug.

3. Verify MySQL is actually reachable on the live port:

   ```powershell
   & "C:\Users\DELL\AppData\Roaming\Local\lightning-services\mysql-8.0.35+4\bin\win64\bin\mysql.exe" `
     -h 127.0.0.1 -P <livePort> -u root -proot -e "SHOW DATABASES;"
   ```

**Fix (this repo):** Pin the port directly in `wp-config.php` so it does not depend on `php.ini`:

```php
/** Database hostname */
define( 'DB_HOST', 'localhost:10175' );
```

This works regardless of what `php.ini` thinks, and was applied for the **Woodmart - Theme Options** site (MySQL port `10175`, site id `uzNsJpwoC`).

**If Local later reassigns a different MySQL port** to this site (rare, but happens on update/port collision), update the `10175` in `wp-config.php` to the new port — or have Local regenerate config by **Stop site → Start site** in the Local app. Default Local sites use `DB_HOST = 'localhost'` and rely on `php.ini` matching; keeping the explicit port is safer for this workspace.

## How the Autoloader Works

Defined in `simple-theme-options.php`:

```php
spl_autoload_register( static function ( $class ) {
    $prefix = STO_NAMESPACE . '\\'; // SimpleThemeOptions\

    if ( strncmp( $prefix, $class, strlen( $prefix ) ) !== 0 ) {
        return;
    }

    $relative_class = substr( $class, strlen( $prefix ) );
    $relative_path  = str_replace( '\\', DIRECTORY_SEPARATOR, $relative_class ) . '.php';
    $file           = STO_INCLUDES . $relative_path;

    if ( is_readable( $file ) ) {
        require_once $file;
    }
} );
```

## Singleton Trait

Located at `includes/Traits/SingletonTrait.php`.

Usage:

```php
namespace SimpleThemeOptions\Admin;

use SimpleThemeOptions\Traits\SingletonTrait;

final class Settings_Page {
    use SingletonTrait;

    protected function init() {
        add_action( 'admin_menu', [ $this, 'register_menu' ] );
    }

    public function register_menu() {
        // ...
    }
}

// Boot it:
Settings_Page::instance();
```

The trait:

- Stores one instance **per class** (so multiple classes can share the trait).
- Calls `init()` automatically the first time `instance()` is called, if it exists.
- Blocks `__clone()` and `__wakeup()` to keep the instance unique.

---

## Bootstrap Flow

1. WordPress loads `simple-theme-options.php` (plugin entry).
2. Constants are defined.
3. `spl_autoload_register` is registered.
4. On `plugins_loaded`, `simple_theme_options()` is called.
5. `\SimpleThemeOptions\Plugin::instance()` runs and calls `init()`.
6. `init()` loads the textdomain and registers any sub-modules.

---

## Adding a New Class

1. Create the file inside `includes/` matching the namespace path. e.g. for `SimpleThemeOptions\Admin\Settings_Page`, create:

   ```
   includes/Admin/Settings_Page.php
   ```

2. Declare it under the proper namespace:

   ```php
   namespace SimpleThemeOptions\Admin;

   use SimpleThemeOptions\Traits\SingletonTrait;

   final class Settings_Page {
       use SingletonTrait;

       protected function init() {
           // hooks here
       }
   }
   ```

3. Register/boot it inside `Plugin::register_hooks()`:

   ```php
   private function register_hooks() {
       \SimpleThemeOptions\Admin\Settings_Page::instance();
   }
   ```

That's it — no manual `require` calls needed. The autoloader handles the rest.
